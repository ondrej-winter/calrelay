# CalRelay implementation plans

Implementation plans decompose accepted work and retain delivery status and
validation evidence. They are not product contracts: accepted behavior belongs
in [`../specs/`](../specs/), durable decisions belong in
[`../adr/`](../adr/), and current reader-facing guidance belongs in the project
references linked from the [documentation index](../README.md).

## Current plans

- [Distribution implementation plan](distribution-implementation-plan.md):
  repository implementation, protected release rollout, and acceptance-evidence
  tracking for the public-beta distribution capability. Read the plan record for
  its current status and remaining checkpoints.

## Maintenance

- Link the accepted specification revision and relevant ADRs.
- Keep sequencing, task status, and implementation evidence in the plan.
- Move stable usage and operational instructions to the owning project reference.
- Do not duplicate or silently revise normative requirements in a plan.
